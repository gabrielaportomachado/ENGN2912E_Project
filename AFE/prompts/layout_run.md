## How to use
- Environment: IIC-OSIC-TOOLS image 2026.04, PDK gf180mcuD at /foss/pdks, repo at /foss/designs/ENGN2912E_Project.
- One fresh Claude Code session per phase, started in the repo root. `git pull` before starting, push after the phase commit.
- Model: Sonnet 5.5; HIGH effort for L2a, L1a, L1d, L3a (layout/CTS, error-prone), default for the rest (budget $700, $129 used on 2026-11-19 before X2). If a phase stops on "the same failure twice", start a new session at HIGH effort only for that fix.
- Order and target dates (target ready 2026-11-25):

- After each phase, paste the agent's summary to the monitoring session (Jojo) for review before starting the next phase.
- If late, cut in this order: (1) L2b/L1b at typ only, (2) skip the optional deep n-well, (3) N = 4 channels (TAPEOUT.md fallback).

## Common rules (every prompt below includes "Follow AFE/prompts/layout_run.md common rules")
1. Read AFE/NOTES.md (Decisions 1-43 and the Results log), AFE/TAPEOUT.md, AFE/layout/PLAN.md and AFE/layout/FLOW.md (once it exists) before working.
2. All geometry is generated by re-runnable scripts (KLayout Python, `klayout -b -r`), N is a parameter, outputs under AFE/layout/. No hand-drawn GDS.
3. Sign-off DRC = the official gf180mcuD KLayout deck; LVS = netgen (always `-batch`, run with a timeout and waited on by PID; `netgen --version` hangs). LVS netlists use cap_mim_2f0_m4m5_noshield (sims used m2m3: substitute by script and record it).
4. Machine limits: ~8 GB RAM, limited disk. At most 3 heavy jobs (ngspice, magic, klayout DRC) in parallel. Scratch under AFE/layout/.ptmp (git-ignored) and delete it at the end. Wait on PIDs, never `pgrep -f`/`pkill -f` (they match their own command line). No `timeout 1800` wrappers around long simulations.
5. Never open *.raw, GDS or PEX netlists in full; use grep/summary scripts. Corners: typical 27 C, ff 85 C, ss -40 C only, unless a result is within 10 % of a limit.
6. If a step fails the same way twice, stop and report instead of trying a third fix. Numbers only from saved logs; mark estimates as ESTIMATE.
7. Write a "<phase> findings" section in AFE/NOTES.md and a Results-log row; commit locally with a clear message; do not push (the human pushes). Do not write a numbered Decision (the human/monitoring session does). Stop at the end of the phase.
8. Simulation rules (Decision 43a, from X2): every transient with switching uses `.options abstol=1e-12` (keep gmin 1e-16 reltol 1e-4 vntol 1e-7 chgtol 1e-17; abstol 1e-15 causes "timestep too small" aborts); one ngspice thread per job (job-local .spiceinit with `set num_threads=1`; the system default is 8 threads and 5-35x slower); never pipe ngspice through `cut` or truncate its log; every supply model with pad L gets ~1 pF per pad to board ground; re-run an aborted job once with a slightly different step cap. Reuse AFE/adc/scripts/x2lib.py (closed-loop PWL replay) for any ADC transient; XSPICE co-simulation is broken here.

Step 1, FLOW-FIRST (time box ~1 h): take one small cell (e.g. one pseudo-R device pair + one 5x5 um MIM unit + one transistor in a guard ring) through the whole chain: KLayout-Python generation -> KLayout DRC -> Magic extraction -> netgen LVS -> Magic PEX netlist that ngspice loads (one .op run). Stop after DRC + LVS (PEX is L2b).
