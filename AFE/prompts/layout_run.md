# Layout run prompts for Atharv (L2a -> L4), one person, one machine

Rewritten 2026-11-20 by phase LP (AFE/prompts/layout_prep.md) on top of a6aff2f; the L2a block is unchanged except for its last line (gate.py). Plain-language guide: **AFE/layout/RUNBOOK.md**.
Every prompt below is self-contained: paste the code block into a fresh Claude Code session started in the repo root. No phase waits for anybody: AFE/layout/ACCEPT.md is IN FORCE (user,
2026-11-20) and the agent decides with its ladder. A phase is done when its gate prints PASS; then commit, `git push`, start the next phase. The user / monitoring session reviews after
the fact through the reports AFE/layout/reports/<phase>.md and answers through AFE/layout/REVIEW.md, which every phase reads first.

## How to use (Atharv)
- Environment: IIC-OSIC-TOOLS image 2026.04 (`hpretl/iic-osic-tools:chipathon26`), PDK gf180mcuD at /foss/pdks, repo at /foss/designs/ENGN2912E_Project. Once per machine: `bash AFE/layout/scripts/check_env.sh` must end with "RESULT: OK" (compare with AFE/layout/sim/check_env_ref.log). If the repo disk has less than 10 GB free: `export AFE_SCRATCH=/tmp/afe_scratch` in every shell before a phase.
- Before every phase: `git pull`. The agent reads AFE/layout/REVIEW.md and applies its open items first (common rule 12).
- One fresh Claude Code session per phase. Model: Sonnet 5.5; effort HIGH for L1a, L1d, L3a (and L2a), default for L2b, L1b, L3b, L4. A phase that stops on "the same failure twice" gets ONE new session at HIGH effort for that fix, then the ladder.
- Run order and parallelism (8 GB RAM, at most 3 heavy jobs at a time machine-wide: the kit's job slots enforce it across sessions):
  | # | Phase | What | Needs | May run in parallel with | Target |
  |---|---|---|---|---|---|
  | 1 | L2a | amplifier cell amp_ch: DRC + LVS | - | - | DONE 11-20 |
  | 2 | L1a | ADC cell adc_ch: DRC + LVS | - | - | DONE 11-20 |
  | 3 | L1d | digital macro afe_dig: final hardening | - | - | DONE 11-20 (branch worktree-l1d-dig) |
  | 3a | REVIEW R2 + R3 | tightened floorplan; afe_dig re-hardened at 820 x 80 um (Decision 48) | L1d | - | 11-21 |
  | 3b | REVIEW R4 | Cin 15 pF: simulations first, then amp_ch re-layout <= 222 x 285 um | R2 | R5 | 11-22 |
  | 3c | REVIEW R5 | adc_ch re-pack <= 222 x 104 um | R2 | R4 | 11-22 |
  | 4 | L2b | amp_ch PEX + post-layout simulations (new cell) | R4 | L1b | 11-23 |
  | 5 | L1b | adc_ch PEX + post-layout simulations (new cell) | R5, R3 | L2b | 11-24 |
  | 6 | L3a | top assembly (bias_genc, decap, straps, TGATEs), full-chip DRC + LVS | L2b, L1b | - | 11-26 |
  | 7 | L3b | post-layout system checks (supply, crosstalk, 8-channel power-up, end-to-end) | L3a | - | 11-28 |
  | 8 | L4 | submission package | L3b | - | 11-29 (official deadline 11-30, Decision 49) |
  Two sessions at once = two terminals in the same repo; each commits only its own files (`git add <paths>`, never `git add -A`); `git pull --rebase` before each commit.
- If a gate fails: the agent follows the decision ladder of AFE/layout/ACCEPT.md section 4 by itself and never waits for a human. Only if no entry applies it writes AFE/layout/BLOCKED.md, commits and pushes it and stops; you continue with a phase that does not depend on it (RUNBOOK.md "what blocks what"); the answer arrives through REVIEW.md.
- If late, cut in this order (all pre-approved in ACCEPT.md): (1) L2b / L1b post-layout runs at typ only (`--corner typ`; compare.py then reports the other corners as missing: use `--allow-missing` and say so), (2) L3b items 3-4 at typ only, (3) N = 4 or N = 2 channels only by ladder A-6 / A-7.

## Common rules (every prompt below includes "Follow AFE/prompts/layout_run.md common rules")
1. Read AFE/NOTES.md (all Decisions, "LP findings" and the Results log), AFE/review/AUDIT.md sections 2, 3 and 4.9, AFE/TAPEOUT.md, AFE/layout/PLAN.md, AFE/layout/SPEC.md, AFE/layout/floorplan.json, AFE/layout/ACCEPT.md, AFE/layout/RUNBOOK.md and, once it exists, AFE/layout/FLOW.md, before working. ACCEPT.md is IN FORCE: decide with it, never wait for an approval. Where SPEC.md / floorplan.json / ACCEPT.md give a number, a pin position or a limit, they win over the prompt text.
2. All geometry is generated by re-runnable scripts (KLayout Python through `bash AFE/layout/scripts/kl.sh <script.py> name=value ...`, helpers in AFE/layout/scripts/kpdk.py), N is a parameter, outputs under AFE/layout/. No hand-drawn GDS.
3. Sign-off DRC = the official gf180mcuD KLayout deck, LVS = netgen, PEX = Magic, ALWAYS through `python3 AFE/layout/scripts/flow.py drc | lvs | pex` (it runs the decks with --variant=D, netgen -batch by PID with a time limit, and the MIM top-plate correction of the PEX; JSON reports in AFE/layout/sim/flow/ that gate.py reads). LVS netlists use cap_mim_2f0_m4m5_noshield.
4. Machine limits: ~8 GB RAM, limited disk. Heavy jobs (ngspice, magic, klayout DRC, LibreLane) go through the job slots (flow.py and the tb_*.py scripts do it themselves; anything else: `bash AFE/layout/scripts/slot.sh <command>`). Scratch under $AFE_SCRATCH or AFE/layout/.ptmp (git-ignored); delete it at the end. Wait on PIDs, never `pgrep -f`/`pkill -f`. No `timeout` wrappers around long simulations.
5. Never open *.raw, GDS or PEX netlists in full; use grep / `flow.py info` / summary scripts. Corners as each phase states.
6. If a step fails the same way twice, apply the matching entry of the AFE/layout/ACCEPT.md decision ladder (section 4); if none applies, write AFE/layout/BLOCKED.md (ACCEPT.md section 6), commit, push and stop instead of trying a third fix. Never wait for a human. Numbers only from saved logs; mark estimates as ESTIMATE.
7. Report: write AFE/layout/reports/<phase>.md from AFE/layout/reports/TEMPLATE.md with its 10 sections ((1) summary and verdict, (2) what was built, (3) exact commands, (4) results table with value, limit, PASS/WARN/FAIL and source log, (5) gate.py output verbatim, (6) every ladder decision with evidence and cost, (7) every deviation from SPEC.md / floorplan.json / the prompt and why, (8) open issues and risks, (9) REVIEW.md items handled, (10) files changed and the commit hash). Also a "## <phase> findings" section in AFE/NOTES.md (just before "## Open questions") and a Results-log row "| date | <phase> ... |". L2a only writes AFE/layout/NOTES_L2.md; the first phase after L2a copies its "L2a findings" and Results-log row into AFE/NOTES.md unchanged AND converts it into AFE/layout/reports/L2a.md (10 sections, from NOTES_L2.md, FLOW.md and the L2a logs). End: `python3 AFE/layout/scripts/gate.py <phase>` must print "GATE <phase>: PASS"; paste its output into section 5; `git add` the phase's own files (never `git add -A`), `git pull --rebase`, commit, write the hash into section 10, commit that, `git push`, stop. A phase that runs longer than about 2 h pushes a checkpoint commit ("<phase> checkpoint: ..."). Do not write a numbered Decision.
8. Simulation rules (Decision 43a, from X2): every transient with switching uses `.options abstol=1e-12` (keep gmin 1e-16 reltol 1e-4 vntol 1e-7 chgtol 1e-17); one ngspice thread per job (job-local .spiceinit with `set num_threads=1`; the kit's runners write it); never pipe ngspice through `cut` or truncate its log; every supply model with pad L gets ~1 pF per pad to board ground; re-run an aborted job once with a slightly different step cap. ADC transients only through AFE/adc/scripts/x2lib.py (closed-loop PWL replay); XSPICE co-simulation is broken here. Post-layout numbers only from the golden testbenches AFE/layout/tb/tb_*.py and AFE/layout/tb/compare.py.
9. Process option: variant D = 5 metals, 11 kA top metal, MIM option B (cap_mim_2f0_m4m5_noshield), high-resistance poly 1 kOhm/sq ONLY (`ppolyf_u_3k` does not exist, Decision 44a).
10. LVS reference netlists are written only by AFE/layout/scripts/mk_lvs_netlists.py (output AFE/layout/lvs/, or a phase's own AFE/layout/<cell dir>/lvs/); never edit a generated reference or a simulation netlist.
11. Crash recovery (any phase): start a new session with the same prompt plus "RESUME: a previous session of this phase stopped half-way". The agent then runs `git status` and `git log`, reads the phase's partial report / findings and the last checkpoint commit, runs `python3 AFE/layout/scripts/gate.py <phase> --no-findings` to see what is already done, and continues from the first FAIL. flow.py reports are reused while the GDS is unchanged (sha1 in the report); tb_*.py scripts merge corners into their JSON, so only missing corners need to run (`--corner <c>`).
12. Feedback: every phase starts with `git pull` and reads AFE/layout/REVIEW.md (written only by the user / monitoring session; never edit it). Apply every open item addressed to this phase, to an earlier phase or to `all` BEFORE the phase's own work: a fix to a finished phase is redone and that phase's gate re-run first (commit + push it as "<earlier phase> fix for R<n>"). List every item handled in report section 9; gate.py fails otherwise.
