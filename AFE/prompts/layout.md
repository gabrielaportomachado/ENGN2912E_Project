# Layout / integration / submission prompts (AFE/layout/) - DRAFT

Start each session with: "Read AFE/NOTES.md and AFE/TAPEOUT.md, then do phase L<n> from AFE/prompts/layout.md."
Same rules as NOTES.md (new files under AFE/ only, numbers from saved logs, stop at the end of each phase, rule 10 for choices).
Additional rules: never open *.raw or large PEX netlists in full (grep/summary scripts only); keep every layout script re-runnable
from a clean checkout; record tool versions; all geometry generated by scripts (KLayout Python or Magic tcl) so N is a parameter.

## L0: Plan (no layout)
Read the PDK design rules for gf180mcuD (MIM min size/spacing, metal stack allowed for MIM, 3.3 V vs 5 V device rules, DNW/guard rings),
the padring repo template and the two example repos (setup99/chipathon-2026-AI_Byte, tritone4801/chipathon-2026-A44-SAR-ADC), and the
tool flow available in this container (magic, klayout, netgen, LibreLane, ngspice, xschem). Propose: tool choice for analog layout
(Magic vs KLayout scripting) with reasons; cell hierarchy and floorplan for N = 8 (amp channel, ADC, routing block, top); how pins and
supplies are routed to the padring; PEX flow (magic extract or klayout) and the post-layout testbench list; LVS flow per block;
a time-boxed schedule to 2026-11-25. Answer the open questions: minimum legal MIM unit (Decision 25), whether power pads count, guard-ring and
substrate-noise plan between the digital (routing/SPI) and analog blocks on the single 3.3 V supply (Decision 30). Write no layout. Stop.

## L1: ADC layout (one ADC cell, replicated per channel: Decision 34; SAR cap DAC, comparator, SAR logic, SPI/config interface)
Generate the layout by script. Cells: unit MIM + binary DAC (matched common-centroid or interdigitated, dummy units), sampling switch,
comparator, SAR/SPI logic (LibreLane digital macro from the D-phase Verilog), NO input mux (one ADC per channel). Run DRC, LVS (netgen), then PEX and re-run the
D-phase transient testbench post-layout; report the change in DNL/INL, settling at T_ACQ and power versus pre-layout. Update NOTES.md. Stop.

## L2: One amplifier channel layout
Generate one channel (stage 1 OTA with large input pair, MIM Cin/Cf, pseudo-resistor, stage 2, follower, bias taps, fast-settle TG) as one
cell with the pins of afe_ch. Pair matching, guard rings, MIM Cin as the dominant block. DRC, LVS, PEX; re-run ac, noise (typical, ff 85 C, ss -40 C),
psrr and the A4b transient set post-layout. Report layout-induced changes against the A4b table and the area actually used. Stop.

## L3: Integration
Assemble top cell: N amplifier channels, routing block (dbs, N = 8, re-run the LibreLane flow in config.json with N = 8), one ADC per channel, bias sharing, the DIN config shift register (Decision 32), tie READY high, no level crossings (single 3.3 V,
Decision 30), supply and ground distribution, guard rings between domains, pin placement to the pad template.
Full-chip DRC, LVS (hierarchical), PEX of critical nets, and one end-to-end post-layout transient: E source -> TGATE (record) -> amp -> its own ADC -> SPI frame, with the REC[7:0] pad nodes observed,
plus one stimulation-mode run. Report final W x H, pin list, power. Stop.

## L4: Submission package
Fill in info.yaml (pin list with io_type per the template comments), lvs_config.json, gds/<top_cell>.gds (core only), SPICE LVS netlist, README (block diagram,
pin description, test plan), documents/Export_Control_GF_Rev8.2.docx (technical answers only, leave signature blank). Run the organizer's checks if available.
List every item that needs a human (signature, repo creation, push). Stop.
