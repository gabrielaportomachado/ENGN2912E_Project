## 7. Deviations
1. AFE/adc/scripts/x2_s4.py is not in the list of files R16 names. It had 8 ADCs hard-coded, so a 4-channel supply run was impossible without it. Change: `NADC = int(os.environ.get('X2_NADC', '8'))` replaces the literal 8 (calibration inputs on ADC 0, (N-1)//2, N-1 = 0, 3, 7 for N = 8; the default decap is the old 0.125 / 0.1 nF for N = 8 and 74 / 30 units for N = 4). Default behaviour is unchanged (regression row in section 4). x2_s5.py (xtalk) imports x2_s4.MODEL, so X2_NADC = 4 gives it the 4-channel decap too.
2. AFE/layout/accept_limits.json: only `why` texts changed (host rule +-300 LSB in three rows, the pwrup8 rows that said 8 channels); no `kind`, `limit` or `soft` changed (checked by script). Needed because ACCEPT.md's table is generated from that file (`--write-accept`).
3. `tb_selftest.sh`, named in the item, does not exist in the repository (mk_fake_pex.py's docstring and ACCEPT.md G-4 name it too). The kit self-test was done with `compare.py --phase L3b --selftest`, `--phase L2b --selftest`, py_compile of every changed script and the N = 8 regression run.
4. tb_top_pwrup8.py: for 4 channels the electrode offsets are 0, -3, +10, -10 mV (the 8-channel set 0, +-1, +-3, +-10, 0 mV does not fit; both signs of the largest offset are kept). T_WAIT stays 5 s at ss -40 C (the 8-channel bias start-up; not re-derived, see section 8).
5. The L3b supply model for N = 4 uses the macro charge of the corner divided by N per ADC per edge, as the 8-channel run did divide by 8 (convention kept). The ss 125 value 15.5 pC is in SUPPLY_BY_N but ss 125 is not part of the baseline (the baseline corners are typ and ff -40, as before).
6. layout_run.md: the rework section R2-R7 is marked HISTORY (all closed) instead of deleted, and the R7 prompt no longer asks for a reports/R7.md that was never written (REVIEW R7 closed as overtaken); this removes the only MISSING of check_prompts.py. The run table gets the rows 3b-3d as DONE; the dates of L3a / L3b / L4 are unchanged.
7. AFE/layout/tb/lptb.py x2_collect: `os.replace` -> `shutil.move` (found by the N = 8 regression run with --out on another file system: "Invalid cross-device link"); no change for the default outputs.
8. Committed besides the named files: AFE/layout/sim/gate_L*.log, sim/check_prompts.log, sim/check_submission_pre.log, sim/post/compare_L2b*.json / .md, sim/post/compare_L3b_selftest.* (outputs of the commands of item E, as in earlier phases).

## 8. Open issues and risks
Open question (not decided): every statement that could not be updated because its number needs a new simulation or a decision.
1. Bias start-up wait: README.md rule 2, AFE/adc/README.md power-up step 2, AFE/adc/SPI_FRAME.md section 4 and the L3b bench T_WAIT = 5 s at ss -40 C rest on `AFE/layout/baseline/bias_startup.json` = t90 3.56 s with the vbn load of 8 channels (tb_bias_startup.py has loads of 8 and 1 channels only). With 4 channels the start-up lies between its 1-channel (0.61 s) and 8-channel (3.56 s) values at ss -40 C; no 4-channel number exists. Needs `tb_bias_startup.py` with N = 4 (cheap, but the file and its baseline are not in R16's list).
2. Power: the 1.05 / 1.64 / 0.68 mW figures (README, TAPEOUT, AFE/adc/README) are an ESTIMATE re-derived by halving the amplifier / vhalf / comparator / DAC columns of f1_power_total.log, keeping one bias cell, replacing the digital column by power_dig.log (17.9 uW at tt) and the DOUT pad by 20 instead of 36 edges per frame (pad load ASSUMED). A new `AFE/review` power run would give measured-in-simulation numbers. Arithmetic per corner (uW, amps / bias / vhalf / digital / comparator / DAC / DOUT = RECORD): typ 909.0 / 18.4 / 84.6 / 17.9 / 1.15 / 0.94 / 13.1 = 1045.0; ff 85 1465.3 / 25.7 / 110.9 / 17.9 / 1.34 / 0.85 / 13.1 = 1635.1; ss -40 568.5 / 13.4 / 65.8 / 17.9 / 1.11 / 1.03 / 13.1 = 680.8; ff -40 3.6 V 1063.0 / 24.0 / 117.2 / 22.0 / 1.34 / 0.93 / 15.6 = 1244.0; ss 125 3.0 V 886.7 / 15.0 / 62.5 / 14.9 / 1.11 / 0.94 / 10.8 = 991.9. The three 3.3 V corners use the tt macro charge.
3. Area: the whole-chip estimate of AFE/review/sim/f1_area.log (0.87 mm2) is an N = 8 number and was replaced by the outline (0.672 mm2) and the placed blocks (0.475 mm2) of floorplan.json; no 4-channel block-sum estimate was recomputed.
4. Supply model constants (Rs 10 ohm, Rd 3 ohm, Rp 0.25 ohm, Lp 2 nH) and the SPEC.md / ACCEPT.md text that quotes X2 what-ifs with 0.125 nF are N = 8-era numbers; only L3b on the real layout (supply_model.json) re-derives them.
5. ACCEPT.md ladder C-3 (macro at 820 x 110 um) and the D-phase rows of the AFE/adc/README.md results table (supply error of "8 ADC cells", whole-chip power 2.09 mW, digital area D3) keep their N = 8 numbers, labelled as such.
6. floorplan.json `cells.afe_dig.what` still reads "dbs_ctrl N = 8 + adc8_top ... channels 4-7 tied off (Decision 52)": the text is generated by floorplan.py and floorplan.json is protected; floorplan.py needs its description string changed and a rebuild (no parameter changes).
7. AFE/layout/PLAN.md (7 hits of 8 channels / 24 pads / 1000 x 1000) and the history sections of AFE/TAPEOUT.md (marked SUPERSEDED) were not rewritten (not named in R16).
8. Results to watch in L3b: the supply plate residue at ff -40 C 3.6 V is 0.559 LSB with 4 channels (0.496 with 8): the ADC-DAC decap halved to 47.8 pF; 0.8 LSB is the pre-approved limit; the ladder S text of ACCEPT.md is unchanged. At typ the residue is 0.174 (0.113): still far below 0.5. The `alt` case has the ADC output code differ by 1 against the ADC alone (ADC 3 within 0.47 LSB of a threshold); x2_s4.py prints "FAIL" for it by its own 0-code criterion, the kit limits do not use dcode_max.

Not a limit row; looked at, not investigated.
